# Wordbook: a private vocabulary notebook

Wordbook is a personal vocabulary notebook built with React 19, TypeScript 5.9, and Vite 8. It is deployed on **Vercel**: the static frontend plus a small `/api` backend (Vercel Functions) that stores **words and categories in a Postgres database**. A single owner signs in with one access password; every signed-in device sees the same notebook. There is no multi-user account system. Language and dictionary preferences still live in each browser.

Look up words, edit drafts, save or delete entries, organize words into multiple categories, search and bulk-classify saved words, practice recall, listen to pronunciation, and export or merge JSON backups. The mobile-first **responsive website** has two hash pages: **My words** (`#/words`, the default) for the library and practice, and **Add word** (`#/add`) for lookup, manual entry, drafts, and a separate import section below. Each page uses a centered single-column layout, with a maximum width of 864px for the library and 640px for Add word; draft forms use two columns from 640px upward. There is no outer composer disclosure or desktop side-by-side library/editor grid. Both route sections stay mounted, with inactive pages hidden, so navigation retains the same controls and session state. This is not a native iOS app or a PWA. The interface uses cool white and dark green, with a bracket and subtle translation highlight. Each saved entry starts as one collapsed whole-word disclosure: its complete word and populated part of speech remain visible, with an independent speech button alongside. Expand it for all saved content, its date, full attribution, license, and secondary delete action; draft attribution remains directly visible on the visible Add word page. Automatic lookup depends on third-party services, but manual entry remains available when requests fail. Pages scroll naturally, without fixed action bars, ARIA tabs, or a modal composer.

The header always shows **中文 | EN** directly, rather than inside a menu, and scrolls with the page. The interface defaults to Chinese rather than following the browser's language. Language changes take effect immediately and are remembered in deployment-scoped `localStorage` when available; otherwise, they still work for the current page. Switching languages preserves drafts, ongoing operations, and practice progress without revealing an answer or moving focus programmatically. Only interface feedback, dates, and recognized source descriptions change their presentation: learning content, Chinese translations, and raw source strings in backups remain unchanged. Speech remains English. Language preferences are not part of entry backups, and system interfaces such as file pickers follow the device's language.

## Using the interface

- **My words** (`#/words`) is the default page, with full-notebook search, display sorting, 20-entry pagination, recall practice, and an export-only **Backup** disclosure. **Add word** (`#/add`) always exposes lookup, manual entry, and any current draft, with **Import backup** in a separate section below. The visible route has one `h1`: **My words** or **Add word**. Add word contains the **Look up or enter** `h2`, **Review and save** draft `h3`, and **Import backup** `h2`.
- Use the two native header links to change pages; the current page is marked with `aria-current="page"` and a non-color-only indicator, not ARIA tabs. The brand link returns to My words without reloading. Modified clicks, middle clicks, and opening in a new tab retain normal link behavior. Links stay in normal flow and may wrap naturally. A missing or unrecognized hash is replaced with `#/words` without adding history or changing the pathname, query, or existing history state. A direct `#/add` visit starts on Add word without first showing My words.
- The native dictionary selector beside the visible **Look up or enter** / **查词或填写** capture heading uses the short labels **FreeDict** and **EnglishDict** for **FreeDictionaryAPI.com (default)** and **EnglishDictionaryAPI.com**. It wraps naturally when space is limited. The selection is remembered for the current browser and deployment directory when storage is available. The visible hint explains: “Switching cancels active lookups; completed drafts stay.” EnglishDict also shows “Accents are not labeled.” Switching affects the next lookup without automatically starting one, changing the input, altering a completed draft or its source, or modifying saved entries. Dictionary switching is unavailable during save, delete, import, and export operations.
- **MyMemory is the fixed service for Chinese completion.** There is no translation-service selector or configuration form. The selected dictionary supplies phonetics, parts of speech, English definitions, and examples. Chinese from the same dictionary sense takes priority; MyMemory fills missing Chinese only. The dictionary and MyMemory requests run in parallel, so MyMemory receives the query even when its translation is not adopted. There are no automatic retries or service changes.
- Enter an English word and choose **Look up** or press Enter. **Fill in manually** is a separate action on its own line. The **Review and save** draft initially shows the word and Chinese translation text area; review and edit it before saving. This draft review is separate from the recall practice described below.
- On Add word, a draft's phonetic preview remains visible outside the optional-fields section. If complete US/UK labels are not recognized, the interface adds “Accent not labeled.” The single phonetic input, part of speech, English definition, and example are in the native **More details (optional)** disclosure. Collapsing it does not clear fields or exclude them from saving. Full attribution, licenses, review guidance, and warnings remain directly visible outside that optional-fields disclosure whenever Add word is visible. Navigating away hides the page without removing the draft or its guidance.
- **My words** uses one initially collapsed native disclosure per entry. Its summary contains the full word and any populated part of speech. The independent 44×44px speech button sits visually alongside the summary, never inside it, and speaking does not toggle the disclosure. Expanding reveals complete phonetics, the full translation, any English definition and example, the creation date, full source and license, and the delete action. There is no nested details disclosure. Manual and older entries still expose their date and any source; optional fields are shown only when populated.
- The secondary trash button inside the expanded entry lets you **delete that entry after confirmation**. Cancelling leaves the notebook unchanged. Deletion cannot be directly undone, but you can add the word again or restore it by importing a backup made before deletion. Unsaved drafts are unaffected. The confirmation message follows the interface language; the browser controls the language of its confirmation buttons. After deletion, only if My words is visible outside practice and its button still owns focus, focus moves to the next visible entry summary, otherwise the previous visible summary, or the collection heading if neither remains; it never reclaims focus moved elsewhere or into a hidden page.
- Search the entire notebook locally by **word or translation**, not just the visible page. Leading and trailing search whitespace is ignored, and matching uses case-insensitive literal substrings, not regular expressions. This search is separate from the English-word network lookup and does not send requests or use its input validation.
- **Recently added** is the default display order: descending database ID, including imported entries, not creation date. **A–Z** uses fixed English collation with a deterministic ID tie-breaker. Sorting applies to all matching results before pagination; neither search nor sorting changes saved content or storage order. Search, sort, result counts, and practice controls form one tighter group rather than a large colored practice-launch card. The visible entry range, matching-result total, total notebook words, and eligible practice answers remain distinct, with the current-results scope, random limit of 10, and blank-answer exclusion explained. No matches offers a clear-search action rather than an empty-notebook message.
- **My words** uses a fixed page size of **20 entries**, with fewer on the final page when needed. Only when results span more than one page, a single bottom row outside the entry list shows **Previous / Page X of Y / Next**. Previous is disabled on the first page and Next on the last; navigation never loops between the last and first pages. The controls may wrap naturally onto another line on narrow screens or with enlarged text. An explicit page turn while My words is visible outside practice focuses and instantly scrolls to the collection heading, without smooth scrolling.
- Changing search or sort, or clearing search, resets to page 1. Saves, deletions, imports, and refreshes retain the current page when valid; otherwise, it is clamped to the last available page (page 1 when no results remain), including while Add word or practice is visible. Later growth does not restore a formerly invalid page. Passive clamping does not programmatically move focus or scroll; deletion retains its separate focus rule above. Pagination state exists only in memory for the current session: reload starts at page 1, with no pagination state in browser storage, the URL, or history state. The two page routes do not encode the current library page.
- Sorting, language changes, background refreshes, route navigation, and entering or leaving practice retain the native open/closed state of surviving keyed entry nodes. Entries outside the visible page or removed by search are unmounted and may return collapsed.
- Expand **Backup** beside the My words heading for export and **Sign out**. Export always reads the entire notebook from the server, not just the current search results or visible page. A short reminder that entries live in the cloud database and should still be backed up stays visible outside the disclosure on My words.
- Opening the site without a valid session shows a **Sign in** form instead of the notebook. If a session expires while you work, the next request switches to the form; drafts and page state stay in memory and the notebook reloads after signing in again. Sign out reloads the page so no notebook data remains in memory.
- On **Add word**, the separate **Import backup** section below capture and the draft offers a native **Overwrite existing words** / **覆盖已有单词** checkbox, unchecked by default. Leave it off to preserve existing content and add new words; turn it on to fully replace matching words' content and creation dates from the backup. Both modes add backup and selected category associations without removing existing ones. Matching ignores surrounding whitespace and letter case. Guidance changes with the option and warns that overwriting cannot be undone: export a backup first. There is no extra confirmation dialog. Choose the import button to open the system file picker. Saving or importing keeps the current route; successful feedback on Add word offers a **View words** link. Import does not clear the current draft or take over focus.
- A successfully loaded empty My words page offers **Add word** and **Import backup** links. The import link navigates to Add word and focuses its import heading; it does not open the file picker. **Try investigation** is on Add word and remains visible only after an authoritative successful read of a truly empty notebook. It prepares an editable built-in draft with the Chinese translation `调查`, without a network request or automatic save. Loading, read failure, no search matches, and matching entries with no eligible practice answers are separate states, not an empty notebook.

The interface has one compact layout, not a separate density mode. With the default 16px root font, body text remains 13px on phones and 14px at desktop widths of at least 1024px, and library words remain 20/22px. Only the practice headword is larger: 32px on phones and 40px at desktop widths of at least 1024px, expressed as `2rem` and `2.5rem`. Text grows with user font settings, and long words, full dual phonetics, and multiline content wrap without ellipses or smaller typography. Text inputs and text areas use at least 16px text. Main controls, page-navigation links, buttons, and disclosure headings are at least 44px high; language, speech, delete, and close buttons are at least 44×44px. The overwrite checkbox stays small and native within an associated label row at least 44px high, rather than using text-input dimensions. The native dictionary and library-sort selectors each size to their longest option and arrow, with a light, transparent appearance. They normally use at least 44px height and 16px text. Only at widths of at least 640px with hover support, a fine primary pointer, and **no coarse pointer** do they use a 32px minimum height and relative body text (`var(--text-body)`): 13px at 640–1023px and 14px at widths of at least 1024px, with the default 16px root font. Touch, hybrid-input, and narrow-screen environments retain the larger targets. Minimum heights, rather than fixed heights, allow the selectors to grow when text is enlarged.

### Categories and bulk organization

- A word can belong to multiple user-named categories without being duplicated. Create, rename, or delete categories in the library's category-management disclosure. Empty categories are retained. Deleting a category requires confirmation and removes only that category and its associations, never the words. Names may be Chinese or English and do not change with the interface language; **All categories** and **Uncategorized** are filter views, not stored categories.
- The native category filter intersects with local word/translation search before sorting and 20-entry pagination. Category names are not part of text search. An empty category, no search matches, and an empty notebook have different meanings; clearing filters resets both text and category conditions. Practice uses all eligible results in that combined scope, across every page, not bulk-selected words. Category labels appear in library summaries, not as extra clues before revealing a practice answer.
- Choose **Select** to enter organization mode. Entry checkboxes are outside the word disclosures, so checking a word does not expand it or trigger speech. Select individual words, all words on the current page, or all filtered results across pages. Selection captures those IDs at that moment; newly matching words are not automatically added. The selected count spans pages.
- Bulk actions **add to**, **remove from**, or **replace** categories and require one or more target categories. A separate **set as uncategorized** action clears all associations. Replace and clear ask for confirmation because they remove current associations. These actions change only category relationships, not content or creation dates.
- Page turns, sorting, and language changes retain selection. Changing search/category scope, leaving the library, entering practice, or cancelling exits selection. Refresh removes deleted words from selection but retains surviving selected words even if they no longer match; the interface reports how many selected words are outside the current results. A successful operation exits that selection; failure retains it for retry. A late completion cannot clear a newer selection or change the route or focus.
- Draft, import, and bulk-target category pickers are independent of each other and the library filter. Each uses native labeled checkboxes and can create a category directly. Creation is saved immediately and selects it only in the initiating picker; cancelling the surrounding workflow does not remove the new empty category. Saving a draft persists its selected associations. Dictionary lookup still fills only the original seven content fields.
- Draft and import category choices survive navigation, language changes, and successful operations for repeated entry, but reset on reload. They are not saved in browser preferences, URLs, or backups. Refresh drops deleted categories from pickers; a deleted active filter returns to all categories and exits bulk mode. If a category selected for a write is deleted in another tab, that write fails atomically rather than recreating it or partially applying the change. Focus/visibility refreshes help reveal changes; there is no real-time synchronization service.

### Page navigation and retained state

Ordinary navigation to the other page adds one browser-history entry; choosing the current page does not. Back and Forward change pages without reloading. Navigation preserves the lookup input, draft edits, text selection, resized text areas, and the inner optional-fields disclosure, together with library search, sort, the valid page, and surviving entry disclosures. Returning to My words restores its saved scroll position. Ordinary navigation to Add word focuses its page heading; an explicit tool call focuses the capture heading, and the empty-library import link focuses the import heading. Returning to My words focuses its heading, except for the practice-return behavior below. Focus does not automatically open the software keyboard. These are session-only states, not autosaved drafts or new persistence; a reload resets them.

Navigation remains available during operations. A lookup, save, import, delete, or refresh that completes after you leave updates shared data and feedback without changing your chosen route or reclaiming focus. Both route sections remain mounted but are hidden when inactive or during practice. Shared status, errors, storage loading/read failures, and retry controls remain outside those hidden sections, so they are also available on a direct Add word visit. Both hashes use the same deployment-scoped database and preferences.

### Short recall practice

1. **Start practice** randomly selects up to 10 entries without replacement from **all current category-and-search results across every page**, excluding blank or whitespace-only translations; bulk selection does not restrict the pool. The visible page does not restrict the practice pool. Any nonblank translation qualifies, including imported answers in languages other than Chinese. No eligible answers is distinct from no search matches. Starting is blocked while the notebook is loading, storage is not ready, or a save, delete, import, or export operation is active.
2. Each word begins with **only the saved word and user-triggered speech** exposed until **Show answer**, with the headword before a short recall instruction. Phonetics, part of speech, translation, definition, example, date, and attribution are absent from the practice answer until reveal, not merely visually hidden. Showing the answer exposes all primary saved content, then the self-rating controls, followed by the complete date and attribution, without truncation or another disclosure layer. The current rating or unrated state remains readable, and returning to a word in the same round retains its reveal state and self-rating.
3. Use **Previous** and **Next** in the compact top navigation/progress strip to browse without rating, keeping both word position and rated count visible. Arrow buttons retain at least 44×44px targets and full localized accessible names, with text labels when space permits. On touch devices, swipe left on the card content for the next word or right for the previous one. Navigation stops at the first and last word rather than looping between them; the corresponding button is disabled and a boundary swipe does nothing. This boundary rule does not prevent controls from wrapping naturally in the layout. Buttons and links remain separate from swiping, and vertical page scrolling, pinch zoom, and text selection remain available. Skipped words stay **unrated**, not missed.
4. After reveal, choose **Didn’t recall** or **Recalled correctly** directly after the primary saved content and before its date and full source/license details. These buttons sit side by side when space allows and wrap naturally for narrow screens or enlarged text; selected ratings remain identified by text and accessible pressed state, not color alone. This is self-feedback, not automatic grading or permanent mastery. Each choice replaces that word's previous rating and automatically advances one position; revisiting a word lets you correct its rating without double-counting. The next word retains its own reveal state, so an unvisited answer stays hidden. The round size stays fixed, and missed words are not appended to it. Rating the last word opens the results even if earlier words are still unrated.
5. **View results** is also available during the round without assigning a rating. A compact results group distinguishes recalled, missed, and unrated words while retaining the round total and whether it is complete. **Continue unrated** is the primary action for a partial round and returns to the first unrated word without resetting progress. Once all words are rated, retrying misses is primary if any remain; returning to the notebook is primary when every word was recalled. **Review this round** remains secondary for a completed round and returns to the last viewed word so its rating can still be corrected. Viewing results does not end the session.
6. **Practice missed words** becomes available only after every word has a rating and at least one was missed. It starts a new round containing only those misses in their previous order, with answers hidden and ratings cleared. The entire started session, including retries, uses copied snapshots of the selected entries. Imports, deletions elsewhere, and background refreshes cannot replace, remove, or refill those snapshots; practice never saves them back. A new session uses the current library.
7. **End practice** discards progress and returns to the same search, sort, page, and scroll context, focusing the initiating Start practice control when usable or the collection heading otherwise without changing that scroll context. Practice is a temporary view within `#/words`, not a third route; Start and End do not add history. Choosing **My words** or the brand during practice uses the same exit, focus, and scroll behavior without a new history entry. Navigating to **Add word** also ends the session; Back does not revive it. External changes may require the page to clamp, and restored scrolling is subject to browser scroll limits. Reload also discards progress and starts the library at page 1. There are no persisted scores, mastery levels, due dates, or schedules, and practice does not write to the server, `localStorage`, `sessionStorage`, or backups. There are no dashboards or practice-generated classifications.

Practice temporarily hides both mounted route sections; drafts, optional-fields and surviving entry disclosure state, and backup controls are retained. External changes can still unmount entries that no longer match or belong to the current page. An already-running lookup may finish into the hidden draft without ending practice, navigating, or moving focus. Shared status, errors, and read retry remain available outside both hidden pages. Keyboard focus moves to the word heading on navigation or returning from results, to the answer heading on reveal, and to the result heading when results open—not on language changes or background refreshes. A new explicit `modelContext` `prepare_vocabulary_entry` call, after existing validation and operation-lock checks, enters Add word and exits practice before awaiting lookup; once visible, the capture heading receives focus without input autofocus or the software keyboard. Invalid or busy calls do not navigate, and late query completion does not navigate or reclaim focus. Tool registration, schema, cancellation, and latest language/dictionary behavior remain unchanged. Practice and local search make no lookup requests; user-triggered speech retains the browser/system service boundaries described below.

## 1. Run locally

[Node.js 24.x](https://nodejs.org/) is recommended. Supported versions are Node.js 22.x from 22.12 onward, or 24.x. The project pins pnpm 11.25.0.

The app needs a Postgres database and two secrets. Put them in **`.env.local`** in the project directory (it is git-ignored):

```sh
DATABASE_URL=postgres://user:password@host/dbname?sslmode=require
WORDBOOK_PASSWORD=a-long-passphrase-you-will-type-to-sign-in
WORDBOOK_SESSION_SECRET=at-least-32-random-characters
```

- `DATABASE_URL` (also accepted as `WORDBOOK_DATABASE_URL` or `POSTGRES_URL`) can point at a local Postgres or at the same hosted database Vercel uses. After linking the project with the Vercel CLI, `vercel env pull .env.local` writes the deployed values into this file.
- `WORDBOOK_PASSWORD` must be at least 8 characters; use a long passphrase, because the site is reachable from the internet. `WORDBOOK_SESSION_SECRET` must be at least 32 characters, for example from `openssl rand -base64 48`.
- Tables are created automatically on the first API request; there is no separate migration step.

Then run:

```sh
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

Open the address printed in the terminal, usually **http://127.0.0.1:5173/**, and sign in. `pnpm dev` serves the same `/api` handler as production through a Vite middleware, so local development reads and writes the database in `DATABASE_URL`. `pnpm preview` serves only the static build, without the API.

Check and build:

```sh
pnpm check
pnpm test
pnpm build
```

Tests run the database code against an in-process Postgres ([PGlite](https://pglite.dev/)); they need no database server or environment variables.

For routing, validate default/unknown hashes, direct Add word visits, root/subpath URLs, Back/Forward, same-route and brand links, native keyboard/modified/new-tab behavior, and shared preference namespaces. Check retained draft nodes and library context, empty-library Add/Import links and sample visibility, export/import placement, practice exits without history or revival, and asynchronous completion without navigation or focus theft. For pagination and categories, validate the 20/21-entry boundary, final-page clamping and later growth even while My words is hidden, combined category/search scope, distinct range and total counts, all-results practice independent of selection, cross-page bulk actions, and whole-notebook export including empty categories. Exercise both backup versions, content overwrite versus association union, different destination IDs, stale-category failures, signing in and out, and session expiry during an operation. Browser checks must also cover explicit versus passive focus/scroll behavior, deletion focus, practice return, and disclosure retention; the [maintenance checklist](MAINTENANCE-ZH.md#validation-checklist) specifies the coverage. These are validation requirements, not a claim of completed checks.

## 2. Deploy to Vercel

1. Push the repository to GitHub. In Vercel, choose **Add New → Project** and import it. The included `vercel.json` sets the Vite framework, `pnpm build`, the `dist` output and the `/api/*` rewrite, so the defaults can stay as they are.
2. Add a Postgres database: in the project, open **Storage** (or the **Marketplace**), create a Postgres database such as **Neon** and connect it to the project. This adds the connection string to the project's environment variables, named after the prefix you choose: `WORDBOOK` (giving `WORDBOOK_DATABASE_URL`), `DATABASE` or `POSTGRES` all work. Connect it to both **Production** and **Preview**.
3. Under **Settings → Environment Variables**, add `WORDBOOK_PASSWORD` and `WORDBOOK_SESSION_SECRET` (requirements above) for Production, and for Preview if you use preview deployments.
4. Deploy (or redeploy after adding variables). Open the production URL and sign in.

Vercel deploys every push: the production branch (set it to `main` under **Settings → Git** to keep the `develop` → `main` release flow) updates production, and other branches get preview URLs. Preview deployments share the connected database unless you configure a separate one, so changes made on a preview URL affect the same notebook. GitHub Actions (`.github/workflows/ci.yml`) only runs type checking, tests and a build; it no longer deploys anywhere.

Changing `WORDBOOK_PASSWORD` or `WORDBOOK_SESSION_SECRET` signs out every device. After ten failed sign-ins within 15 minutes, sign-in is paused for everyone until the window passes.

The Vercel Hobby plan is free for personal, non-commercial use; check Vercel's and your database provider's current limits before relying on them.

### Moving from the GitHub Pages version

The former GitHub Pages build kept entries only in each browser's IndexedDB. Nothing is moved automatically:

1. **Before disabling or replacing the Pages site**, open it in every browser that has entries and choose **Backup → Export backup**.
2. Sign in to the Vercel deployment, open **Add word → Import backup**, and import each file. Imports merge by word and category name, so importing several devices' backups combines them.
3. After checking the imported notebook, you can turn off GitHub Pages under **Settings → Pages** in the repository. This workflow no longer publishes to it, so the old site keeps serving the last Pages build until you do.

## 3. JSON backups and transfers

- Expand **Backup** beside **My words**, then choose **Export backup** to download JSON for the entire notebook and its complete category directory, including empty categories, regardless of search, category filter, bulk selection, display order, or visible page. Page state, picker choices, and practice progress are not included. Check that the download is saved somewhere reliable and retain multiple dated copies. Backups contain private entries and category names and **are not encrypted**; do not put them in a public repository.
- In the target browser or at the target address, open **Add word** (`#/add`), then choose **Import backup** in the separate section below capture and the draft to select a Wordbook JSON file in the system file picker. The empty My words page's import link only navigates to that heading; it does not open the picker. With **Overwrite existing words** unchecked (the default), import adds new words and preserves every existing word's content and `created` timestamp, but can still add category associations. Newly imported words retain their backup timestamps. Import preserves the current draft, route, and focus; successful feedback on Add word offers a **View words** link. You can choose the same file again because the input is cleared after each selection.
- In both modes, associations become **existing categories ∪ backup categories ∪ categories selected for this import**. Imports only add associations; they never remove existing ones. A legacy v1 backup has no category associations and cannot clear local ones. Select zero or more additional categories in the import picker independently of draft and bulk choices.
- With overwrite checked, matching words' seven content fields and `created` are fully replaced, including empty fields and raw `source`; these values are not merged field by field. Their local IDs and existing category associations remain. Unrelated local words stay untouched. Words are matched after trimming and lowercasing, and the first normalized occurrence within the file wins for both content and associations; later duplicates are skipped. The entire category directory is still imported, including categories used only by a skipped duplicate.
- Completion reports **Added / Overwrote / Skipped**, plus the number of words that gained associations and categories created. The first three counts sum to the file's entry count. A chosen existing match counts as overwritten even when its content is identical. A word gaining one or more associations counts once, including a new categorized word; this count overlaps the content counts and must not be added to them as a total. Reimporting unchanged associations does not count them again. Created categories include empty ones, so a category-only import can succeed without adding words.
- The overwrite checkbox and import category choices exist only in memory: they survive page navigation, language changes, and import completion, but a browser refresh resets them. Controls are unavailable while an operation is busy or the notebook is not ready. Both mode and selected category IDs are frozen when the file is selected, before reading begins. Guidance follows the selected mode and warns that **overwriting cannot be undone; export a backup first**. Import does not open an extra confirmation dialog.
- A backup exported after deleting a word excludes that word, but retains any now-empty categories. Earlier backup files are unchanged and can restore their entries through import. Deletion affects the shared notebook on every device, but not existing backup files.
- New exports use **v2**: `{ format: 'wordbook', version: 2, exportedAt, categories, entries }`. The root `categories` is a directory of names, and each entry contains the seven content fields, `created`, and a required `categories` array of names from that directory, including `[]` for an uncategorized word. Phonetics remain a single string, preserving labeled dual phonetics and older IPA text. Entries are exported in ascending local-ID order; category names and references use deterministic normalized-name order. Neither word/category IDs nor internal name keys, dictionary/language preferences, or selection state are exported.
- The current app also reads exact **v1** envelopes `{ format: 'wordbook', version: 1, exportedAt, entries }`; category-looking extras inside v1 entries retain their old ignored meaning. Older apps cannot read v2, and there is no category-losing v1 export option. Only additions receive new local word IDs; an overwritten match retains its original positive ID and its **Recently added** position. Do not import arbitrary JSON or old database files as backups.
- Categories are restored by normalized **name**, not by another device's numeric ID. Matching categories reuse the target notebook's ID and displayed name. Missing names create categories, including empty ones. This is **name-based merging, not rename synchronization**: restoring a backup made before a category rename can recreate the old name alongside the renamed category.
- Each backup is limited to **10 MiB (10,485,760 UTF-8 bytes), 10,000 entries, and 1,000 categories**; each entry may contain at most 1,000 category references. Names are trimmed and NFC-normalized, limited to 1–80 UTF-16 code units without control characters, and matched case-insensitively without collapsing internal spaces or stripping accents. Duplicate normalized directory names and undeclared references reject the file; repeated references within one entry are deduplicated. The entire file is validated, including entries that will be skipped. All word and category changes commit together in one database transaction; invalid files and failed transactions leave existing data intact. Large files are gzip-compressed in the browser before upload. The merged library must also stay within 1,000 categories, and selected categories must still exist when the transaction runs. Counts are reported only after commit. Export applies the same field, count, relationship, and size checks and never silently truncates the backup.
- Every signed-in device and browser uses the same notebook, so moving devices needs no transfer. Backups remain the way to restore after a mistake or to move to another database.

Historical SQLite data is **not migrated automatically**. Keep those databases and existing backups. There is no SQLite importer; convert data separately into the supported JSON format or enter it manually.

## 4. Data, privacy, and service boundaries

- Website code and static assets are public to visitors. Never put passwords, tokens, or secrets in frontend source or build variables; `WORDBOOK_PASSWORD`, `WORDBOOK_SESSION_SECRET` and `DATABASE_URL` are server-side environment variables only.
- Words and categories are stored in the Postgres database you connect, and are only as private as that database and its provider. Every API route except sign-in requires the session cookie. The cookie is `HttpOnly`, `SameSite=Strict` and `Secure` on HTTPS, lasts 30 days, and is signed with a key derived from both secrets. Write requests also require a custom request header, so other sites cannot submit changes with your cookie.
- There is a single access password and no per-user data separation. Anyone who knows the password can read and change the whole notebook; use a long passphrase and change it (which signs everyone out) if it may have leaked.
- Hosted databases have their own backup and retention policies; JSON exports are still the portable backup you control.
- Language and dictionary preferences stay in each browser's `localStorage`, namespaced by deployment directory (the `wordbook:` prefix), and are not synchronized.
- **Retired translation settings:** Visit the updated app in the same browser profile at each specific origin and deployment directory where it was used to attempt cleanup. Each mount/reload silently tries to remove only `localStorage` keys `${databaseName(location.href)}:baiduCredentials` and `${databaseName(location.href)}:translationProvider`, without reading or logging old values. Removal is best-effort; failures are retried on later mounts/reloads, and publishing the update alone does not establish successful cleanup. Saved words, backups, language/dictionary preferences, other namespaces, unnamespaced lookalikes, and `sessionStorage` are untouched. The retired service is not restored. **Do not clear all site data for this cleanup.**
- Network lookups contact **only the selected dictionary and MyMemory**, in parallel. FreeDictionaryAPI.com (`freedictionaryapi.com`) or EnglishDictionaryAPI.com (`englishdictionaryapi.com`), plus MyMemory (`api.mymemory.translated.net`), receive the query word. The unselected dictionary does not. Both requests use `credentials: 'omit'` and `referrerPolicy: 'no-referrer'`; this does not make queries anonymous to the services. Each request has its own 30-second timeout, with no automatic retry or switch to another service. Cancellation stops local waiting and acceptance of results; it cannot retract a request already received upstream.
- Chinese from the selected dictionary sense takes priority; MyMemory fills missing Chinese only. A failed translation request does not discard successful dictionary content, and a failed dictionary request can still leave a usable Chinese translation. Missing fields remain editable, and saved entries are unaffected. The raw source label `MyMemory（机器翻译）` is recorded only when MyMemory's translation fills the Chinese field. Machine translation is not covered by the dictionary's Wiktionary license, and changing the dictionary or interface language does not relabel saved sources.
- Both dictionaries and the MyMemory lookup used here work without user-supplied API keys. Network conditions, cross-origin policies, usage limits, and content coverage can prevent successful lookup; continued availability is not guaranteed. See MyMemory's [API documentation](https://mymemory.translated.net/doc/spec.php) and [usage limits](https://mymemory.translated.net/doc/usagelimits.php) for its current requirements. The project does not promise a fixed quota or unrestricted reuse of translation output.
- Both dictionaries provide Wiktionary content under CC BY-SA 4.0. Wordbook displays links to the service, original article, and license, and retains attribution with entries and JSON backups. EnglishDictionaryAPI.com does not return per-entry source or license fields: Wordbook safely constructs an article link from the matching original query and uses the license documented by the service. Editing the word or switching dictionaries does not rewrite recorded attribution. Redistribution must preserve attribution, license information, and modification notices, and comply with ShareAlike and other applicable license requirements.
- FreeDictionaryAPI.com phonetics come only from the selected English entry. Exact tags `US` or `General American` identify US pronunciation; `UK` or `Received Pronunciation` identify UK pronunciation, after trimming and case-insensitive comparison. When both are confirmed, the display is such as `US /təˈmeɪ.toʊ/ · UK /təˈmɑː.təʊ/`, with US first. If only one is confirmed, only that accent is shown; accents are not assembled across entries. If neither is confirmed, the first valid IPA is retained as written. When the 2,000-character limit would be exceeded, complete segments that fit are retained in US-then-UK order, and omitted segments produce a warning; IPA and labels are never cut mid-segment.
- EnglishDictionaryAPI.com supplies a single word-level IPA without accent metadata. The interface displays “Accent not labeled”; it does not guess from audio URLs or IPA spelling. Older, manual, and imported phonetics are not rewritten. Only complete explicit US/UK labels are recognized for presentation; other formats retain their text and receive the display-only hint. The editable phonetic value is still one string, so no backup-version change is needed.
- Speech uses the browser or system speech facility, not dictionary recordings. Each click prefers an available `en-US` voice. Changing the interface language or dictionary does not change this preference. If voices have not loaded or no US voice is available, the app still requests `en-US`, but the actual accent depends on the device. Some voices may process text online; speech is not guaranteed to be available or offline.
- Browser mocks and viewport or touch emulation cannot establish live-service availability or real iPhone Safari compatibility. Real-device keyboard behavior, safe areas, VoiceOver, file handling, and speech require separate manual verification. A checklist is not a record of completed validation.
- This is not a PWA and has no offline mode: viewing, saving, and practice-start refreshes need a connection to the server. There is no password-reset flow; the password is whatever `WORDBOOK_PASSWORD` is set to.
