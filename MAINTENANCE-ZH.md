# Wordbook maintenance guide

Wordbook is a frontend-only React, TypeScript, and Vite application. See [README-ZH.md](README-ZH.md) for setup, usage, backups, and deployment, and [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) for third-party content and dependency licenses.

## File responsibilities

| Responsibility | File |
| --- | --- |
| Page structure, controls, entry display, and interaction | `src/page.tsx` |
| Chinese and English UI messages, formatting, and language preference | `src/i18n.ts` |
| Structured message identifiers, parameters, and errors | `src/messages.ts` |
| Colors, typography, layout, and responsive styles | `src/style.css` |
| Frontend entry point | `src/main.tsx` |
| Entry types, shared validation, and the `investigation` sample | `src/entry.ts` |
| Parallel selected-dictionary and fixed-MyMemory lookup, partial success, and result normalization | `src/vocabulary.ts` |
| Dictionary identifiers, default, browser preference, and scoped legacy translation-preference cleanup | `src/dictionary-providers.ts` |
| IPA candidates and formatting and recognition of complete US/UK labels | `src/phonetics.ts` |
| IndexedDB setup, reads, saves, deletion, and transactions | `src/storage.ts` |
| JSON backup format, validation, export, and merge import | `src/backup.ts` |
| Automated tests | `tests/` |
| Build configuration and third-party notice emission | `vite.config.ts` |
| Node.js and pnpm versions, scripts, and dependencies | `package.json`, `pnpm-lock.yaml` |
| GitHub Pages build and deployment | `.github/workflows/deploy.yml` |

Data flows from the page through `storage.ts` to IndexedDB, from lookup through `vocabulary.ts` to third-party APIs, and through `backup.ts` to JSON files or validated transactional imports. There is no application-owned HTTP API. Dictionary selection has exactly two options; MyMemory is the fixed Chinese-completion service, not a configurable translation-provider framework.

## Development and checks

After changes, run:

```sh
pnpm check
pnpm test
pnpm build
pnpm preview
```

- `check` runs TypeScript type checking.
- `test` runs `node:test` through `tsx`. IndexedDB tests use `fake-indexeddb`, which is not a real-browser test.
- `build` generates `dist/`, including static assets and `THIRD-PARTY-NOTICES.md`.
- `preview` serves an existing build. Rebuild after source changes; preview is not a production deployment service.

Use pnpm to update dependencies and keep `package.json` and `pnpm-lock.yaml` together. Do not generate additional lockfiles with another package manager. If CI's frozen install fails, reconcile the dependency manifest and lockfile rather than removing `--frozen-lockfile`. In `pnpm-workspace.yaml`, keep `esbuild: true` for its required postinstall and `fsevents: false` to explicitly deny build-script permission; the retained `fsevents` dependency ships its native binary, and the explicit decision avoids undecided build approval in existing installations.

## Language policy

- Write code identifiers, comments, test titles, static developer-facing metadata, and project documentation in natural, precise English. This applies to static `modelContext` tool titles and descriptions as well as build and workflow commentary.
- Preserve the complete `zh-CN` and `en` UI catalogs, Chinese learning content and sample data, persisted raw source literals, and intentional Unicode test fixtures. These are application data or localization resources, not prose to translate indiscriminately. Do not change their values or expectations merely to make files look English.
- Keep runtime UI feedback localized. Static English tool metadata does not make runtime warnings or readable errors English-only. Page metadata that follows the selected UI language remains localized.
- Treat unknown historical source strings as opaque data. Do not reinterpret, relabel, or migrate them, or widen the link allowlist to turn unknown text into links.

## Data contracts

- Trim words, normalize them to lowercase, and enforce uniqueness. List entries in descending database-ID order, not by creation time.
- IndexedDB remains version 1. Database names are `wordbook:` plus the normalized deployment directory. Changing naming, origin, or path can affect which data is visible; directory-based names are not same-origin security isolation.
- Backups use `format: 'wordbook'` and `version: 1`. The seven entry fields remain `word`, `phonetic`, `translation`, `pos`, `definition`, `example`, and `source`. A single `phonetic: string` accommodates labeled dual or single pronunciations and older IPA text; do not change the `entry.ts`, `storage.ts`, or `backup.ts` contracts for presentation changes. Preserve `created` as a UTC ISO timestamp. Do not export database IDs or dictionary and language preferences. Validate the entire file before merging it in a transaction. Existing entries win; among duplicate words within the file, the first wins. Import does not overwrite existing content.
- Both import and export enforce field validation, the 10 MiB size limit, and the 10,000-entry limit. Failure must not clear the original database or commit partial data. Report success only after transaction completion.
- Delete with `remove(id)`, accepting only positive safe-integer IDs and reporting success only after the read-write transaction commits. A nonexistent ID is an idempotent success. Do not delete by word, which could let a stale page remove a newly re-added entry with the same word. Deletion does not change the schema or database version. Subsequent exports exclude deleted entries; importing an older backup can restore their content and creation times with new IDs. Do not add tombstones or a recycle bin.
- Preserve raw `source` values through saving, display formatting, and backup round trips. Interface-language changes must not rewrite stored Chinese source literals. Do not add storage cleanup or migrations as part of language or presentation work.
- Do not promise accounts, automatic synchronization, PWA support, or automatic migration of historical SQLite data. Keep private backups, historical databases, and secrets out of source, test fixtures, and deployment artifacts.

### Scoped legacy translation-preference cleanup

- This explicitly requested cleanup is separate from language conversion or presentation work; the prohibition above on incidental cleanup still applies. Do not restore the retired translation service or its settings UI.
- Call `removeLegacyTranslationPreferences` from `src/dictionary-providers.ts` in the existing `src/page.tsx` mount effect, before store loading. Use a lazy storage getter exposing only `removeItem`. Attempt removal of exactly `${databaseName(location.href)}:baiduCredentials` and `${databaseName(location.href)}:translationProvider` from the current origin/directory namespace in `localStorage`; never read or log old values. Return normally if storage access fails. Handle removal failures independently so one blocked key does not suppress the other attempt. Neither failure blocks store loading or produces a page warning. Retry on every mount/reload, with no completion marker. The updated app must be visited at each specific origin and deployment directory to attempt cleanup; publication alone proves no real-user cleanup.
- Never enumerate or bulk-clear storage. Preserve saved words, IndexedDB version 1, backup version 1, locale and dictionary preferences, other namespaces, unnamespaced lookalike keys, and all `sessionStorage`.

## Interface language and messages

- Default to `zh-CN`; let the header switch to `en`. Read and write the preference defensively at `${databaseName(location.href)}:locale`, without changing the database name or backup format. Invalid values and read failures fall back to Chinese; write failures must not prevent switching for the current page.
- Maintain UI messages in `i18n.ts`. Business logic passes `Message` and `MessageError`; the page retains structured errors, notices, and warnings and formats them at render time. Add both translations and their parameters together. Unknown exceptions receive a localized generic message, not arbitrary `Error.message` text.
- Localize controls and feedback, not entry text, Chinese translations, raw `source`, or UTC timestamps. Localize recognized source descriptions only on exact matches; retain unknown values verbatim and preserve the existing HTTPS link allowlist. Format dates and page metadata for the selected locale. Speech still uses `en-US`.
- Do not make locale part of the database, focus-listener, or tool-registration lifecycle, or use it as a component key. Language switching must not clear drafts or cancel lookups. Language buttons remain available during business operations and retain native focus behavior.
- Keep static `modelContext` tool titles and descriptions in English, with stable identifiers, schema, and registration lifecycle. At completion, use the synchronously updated `localeRef` to format runtime warnings in the latest selected language. Convert only recognized `MessageError` instances into readable errors, preserving their original `cause`. Do not wrap unknown exceptions or cancellation reasons, or change their identity.

## Responsive layout and iPhone maintenance

### Shared structure and visual design

- Maintain one mobile-first responsive website. Phones use one column. At widths of at least 1024px, use a 1160px maximum-width desktop layout with lookup and editing on the left and the word list on the right; the left area is 320px wide and the column gap is 24px. Keep `.composer` mounted as a wrapper around the existing lookup, feedback, and conditional draft, not a second form. Align both grid areas at the top. Do not add fixed or sticky panels, internal scrolling, or a list that stretches the editing area. Remove the single-column top margin from the desktop word list.
- Keep one `Home` component and one state tree. Do not create separate phone components, a native iOS app, or a PWA. Breakpoints and orientation must not be component keys. Entries keep stable IDs, and layout changes must not remount forms or steal focus. Show `中文 | EN` directly in the normal-flow header, not in a menu or fixed bar.
- Use cool white, dark green, and pale yellow-green annotations. Keep colors, type sizes, and spacing in `style.css` tokens and existing rules rather than accumulating overrides or adding a density mode. Word headings and the wordmark use a system serif stack such as Charter; controls and Chinese text use system sans-serif fallbacks such as PingFang SC; dates and counts use system monospace. Do not download or redistribute system fonts.
- The translation bracket connects only the word heading, phonetics or part of speech, and Chinese translation, with a 16px inset and 6px top gap before the translation. The highlight follows the actual translation text and supports wrapping. Keep the same wrapper without drawing the bracket or highlight when the translation is absent. Definitions, examples, dates, and attribution remain outside the bracket. Do not turn each entry into a separate colored card.
- Use `rem` typography. At a default 16px root size, body text, Chinese translations, definitions, and examples are 13px on phones and 14px at desktop widths of at least 1024px (`0.8125rem` and `0.875rem`). Word headings are 20/22px, section headings 14/16px, and the wordmark 22/24px. IPA uses a 13px-equivalent relative size; form labels, helper text, dates, and sources use 12px-equivalent relative sizes. Ordinary button text follows the body size. Line heights are about 1.6 for body text, 1.5 for auxiliary text, and 1.25 for headings. Do not shrink the root font, use `zoom` or `transform: scale()`, or truncate long words, complete dual phonetics, or multiline content.
- Keep the header at least 56px high with 6px vertical padding. Main content starts 16px below it. Lookup-area padding is 12px on phones and 16px from 640px upward; the single-column word list has a 20px top gap. Entries use 10px vertical padding on phones and 12px at desktop widths of at least 1024px, separated by padding and rules without an additional entry gap. Use a 16px draft separator, field gaps of 8px on phones and 12px on desktop, and 4px label gaps. Text areas start at two rows and allow vertical resizing. Never clear hidden fields.

### Drafts, entries, and backup controls

- Keep Enter submission and manual entry available during lookup. Drafts initially show the word and Chinese translation text area; translation may be empty and has a 2,000-character limit. If phonetics exist, show a preview from the same draft value outside the disclosure, adding “Accent not labeled” when complete US/UK labels are not recognized. Keep the single phonetic input, part of speech, definition, and example inside the initially collapsed native **More details (optional)** `details` element. Do not add duplicate phonetic state. Fields remain mounted and are saved even when collapsed. Place Save directly after the disclosure. Full attribution, licenses, review guidance, and warnings must not be hidden; failed saves retain the draft.
- Saved entries show the full word, speech control, existing phonetics and part of speech, and complete Chinese translation. Preserve dual phonetics and the unlabeled-accent hint. Every saved entry has a valid creation date, so every entry needs a native **Details & source** disclosure; do not gate it on `definition || example`. Put any definition and example, the `formatDate()` date, and the complete `Source` inside. Manual and older entries without a definition or example must still expose their date and any source. Render optional fields only when populated, without empty placeholders.
- Retain full attribution, Wiktionary and license links, modification notices, adopted MyMemory attribution, and opaque historical source values. Collapsing details must not change source parsing, links, or stored strings. Do not duplicate footer indentation or restore the old source `24rem` flex-basis. Use stable entry IDs and native disclosure state, without locale keys or controlled `open={false}`. Show **Try investigation** only after a successful read of an empty notebook. Reuse `openDraft(sample)` without requests or automatic writes. Loading and read-error states remain distinct from an empty notebook.
- Provide a delete button of at least 44×44px beside the speech button, with an accessible name containing the word. The native confirmation message follows the interface language; system buttons follow the browser language. Confirmation and deletion share the synchronous operation lock. Cancellation or failure leaves the entry in the list; update by ID only after success.
- Use `aria-disabled` with lock and readiness checks on delete controls to preserve focus. After deletion, move focus only if the triggering button still had focus: choose the next entry's speech button, otherwise the previous one, or the word-list heading if empty. Do not reclaim focus that the user moved elsewhere. Window-focus refreshes and post-write reads are silent; loading or error messages must not replace the keyed entry list. Preserve neighboring disclosures and draft nodes. Report a failed refresh after successful deletion separately, not as a failed deletion.
- Put **Backup** beside **My words** in native `details`. Import, export, and merge guidance expand in normal document flow, not a floating menu. Keep the local-storage, no-sync, and regular-backup reminder outside the disclosure. Keep feedback outside collapsed content. The file input stays mounted, uses its existing `accept`, opens through a direct user action, and clears `value` after selection so the same file can be chosen again.
- Wrap the lookup row according to actual available space, not viewport width alone. Give the input a preferred/minimum allocation of about 10rem, capped by available width. Move the button to another line when needed and stack vertically at widths up to 359px. Manual entry remains a separate action row at least 44px high. Check “Looking up…” in the narrow desktop editing column and allow natural height growth. Draft fields use two columns at 640–1023px and return to one column at 1024px and above, with a full-width Save button. Do not retain nested draft borders or padding. Backup feedback continues to use the existing workspace live region, without duplicate announcements or automatic scrolling.

### Input, accessibility, and native selection

- Set `autoCapitalize="none"`, `autoCorrect="off"`, and `spellCheck={false}` on the lookup input and draft English-word field, with `enterKeyHint` values of `search` and `next` respectively. Do not impose English input behavior on Chinese fields or open the software keyboard on page load.
- Inputs and text areas use `max(16px, 1rem)` to avoid iPhone focus zoom, with 9px vertical padding. Main controls, buttons, and `summary` elements are at least 44px high. Language, close, speech, and delete buttons are at least 44×44px.
- Keep one native dictionary selector. Size it and its wrapper to the longest option plus the native arrow, capped by available space. Use a transparent background and `4px 8px` padding. By default, use at least 44px height and `max(16px, 1rem)` text. Only when width is at least 640px, `hover: hover`, and `pointer: fine`, with no `any-pointer: coarse`, use a minimum height of 32px and relative body text through `var(--text-body)`: `0.8125rem` at 640–1023px and `0.875rem` at widths of at least 1024px, equivalent to 13px and 14px with the default 16px root font. Touch, hybrid-input, and narrow-screen environments retain the default 44px/16px minimums. Use minimum rather than fixed heights so enlarged text can grow the control. Do not draw a replacement arrow or substitute a custom menu. There is no Chinese-completion selector or service-settings form.
- Preserve associated labels, accessible icon-button names, visible focus, user zoom, and reduced-motion support. Do not nest buttons inside `summary`. Avoid duplicate status and error announcements. Source links remain naturally inline with appropriate spacing and visible focus; do not make every attribution fragment a large button.
- Keep `viewport-fit=cover` in `index.html` and handle all four `safe-area-inset-*` values once at the outer layout. Use `min-height: 100vh` as a fallback with `100svh` progressive enhancement. Preserve natural page scrolling, without fixed page height, internal scroll regions, or a fixed Save bar. Wrap long words, phonetics, translations, examples, and sources. Do not mask layout overflow with `overflow-x: hidden`.
- Layout and disclosures must not change lookup cancellation and generation guards, synchronous `operationLock`, storage readiness, unmount protection, or focus refreshes. Preserve `localeRef`, `modelContext` registration lifetime, and cancellation identity. Do not add phone-specific business logic or change data, transaction, or lookup contracts.

## Lookup and attribution contracts

- Dictionary IDs remain `free-dictionary` for the default FreeDictionaryAPI.com and `english-dictionary` for EnglishDictionaryAPI.com. Read and write the preference defensively at `${databaseName(location.href)}:dictionaryProvider` in `localStorage`. Invalid values or read failures fall back to the default; write failure still permits a current-page selection. Preferences do not change the database name and are not included in entries or backups.
- Place the lookup `h1` and native selector in one wrapping header. Keep a genuinely associated label, visually hidden with `sr-only` if appropriate; `title` alone is not a label. Options use **FreeDict** and **EnglishDict**, with complete service names in the selector and option `title` attributes. Do not repeat those names below the selector. Size to content instead of a fixed 9.5rem width, allow natural flex wrapping, and do not clip the option text or native arrow.
- Keep `dictionary-hint` in normal document flow below the header and associate it through `aria-describedby`. Its UI text is “Switching cancels active lookups; completed drafts stay.” / `切换会取消当前查询，保留已完成草稿。`; EnglishDict adds “Accents are not labeled.” / `此词典不标注口音。`. Do not put this guidance only in a tooltip. Attribution continues to use complete service names; short selector aliases never enter stored data.
- Switching dictionaries calls `cancelLookup()`, aborting both in-flight requests and invalidating their generation while retaining input, completed drafts and edits, warnings, sources, and saved entries. It must not automatically query, save, or merge. Allow switching during lookup, but disable it during save, delete, import, and export and enforce the synchronous `operationLock` in handlers. Pair state with the synchronous `providerRef` and snapshot the selected dictionary at lookup start. Registered `modelContext` tools read the latest selection without re-registering or changing schema. Preserve generation guards on success, failure, and `finally`.
- The browser directly requests **only the selected dictionary and fixed MyMemory**, in parallel. Do not automatically retry, visit the unselected dictionary, or choose another translation service. Each request has an independent 30-second deadline and retains `credentials: 'omit'` and `referrerPolicy: 'no-referrer'`. Preserve `Promise.allSettled()`, outer cancellation, the final cancellation check, and partial-success drafts. Wait for both branches to settle; do not serialize them. Invalid input and the built-in `investigation` sample return without a network request. Failure still permits manual entry. Local cancellation cannot retract a query already received by an upstream service.
- FreeDictionaryAPI.com uses `/api/v1/entries/en/{word}?translations=true`. Match the normalized query exactly and use English entries only. Select the definition, example, and `cmn`/`zh` Chinese translations from the same sense, including subsenses, without mixing senses. Dictionary Chinese takes priority over MyMemory; missing fields stay empty. Text fields retain their 2,000-character limits.
- FreeDictionary phonetics come only from the selected English entry, not other entries or parts of speech. Match `tags` exactly against `US` / `General American` and `UK` / `Received Pronunciation`, after trimming and case-insensitive comparison; ignore invalid tags defensively. Use the first valid upstream IPA for each confirmed accent, US first. Format both as `US /…/ · UK /…/`, or one as `US /…/` or `UK /…/`. Keep both labels if an identical IPA is explicitly tagged for both. When any accent is confirmed, include confirmed accents only. Otherwise, retain the first valid IPA as written; if all are invalid, leave the field empty and report the missing value.
- Do not pass IPA through `text()`, which truncates early. The combined limit remains 2,000 characters. In US-then-UK order, retain whole segments that fit; omit complete segments that do not and report a localized warning. Unlabeled IPA must not be partially truncated either. `phonetics.ts` handles temporary candidates and conservative recognition of complete labels; do not add a persisted pronunciation object or duplicate draft state. Do not infer labels for, or rewrite, older entries, the sample, manual content, or imports. Unrecognized formats keep their text and receive a display-only “Accent not labeled” hint. Both UI languages retain US/UK labels, and editing uses one field.
- EnglishDictionaryAPI.com uses `/api/v1/words/{word}`. Its returned `word` must exactly match the normalized query. Select the first `partsOfSpeech` group with a valid definition, then prefer a sense containing both a definition and nonempty example; otherwise use its first valid definition. Do not combine different senses. Chinese completion comes from MyMemory. Read only word-level `pronunciation.ipa`, ignoring null, invalid, and empty values, rather than part-of-speech phonetics or `enpr`. The single IPA has no accent metadata; do not infer a region from `audioUrl` or the IPA text, and do not request dictionary recordings.
- MyMemory uses `https://api.mymemory.translated.net/get?q={encodedWord}&langpair=en%7Czh-CN`. Accept a successful response with usable Chinese text; retain the existing text normalization and field-length limit. Adopt it only when the dictionary has not supplied Chinese. If either branch fails or supplies unusable content, preserve usable content from the other and report missing fields through localized messages. MyMemory provides Chinese completion, not dictionary phonetics, parts of speech, English definitions, examples, or dictionary license metadata.
- Before adopting FreeDictionary content, validate its response's HTTPS Wiktionary article URL and CC BY-SA 4.0 license metadata. EnglishDictionary's official documentation identifies English Wiktionary / CC BY-SA 4.0 content and a 2026-06-01 data dump, but its responses lack per-entry source and license fields. Only for matching adopted content, construct a link from the fixed `https://en.wiktionary.org/wiki/` prefix and the validated, encoded original query, then validate it with `wiktionaryUrl()`. Do not describe this constructed URL as API-supplied metadata.
- `source` remains a string with the dictionary form `<dictionary name> | Wiktionary: <article URL> | CC BY-SA 4.0: <license URL> | 词典摘录，可经编辑`. Use only the exact service names for recognized dictionary attribution. Append the exact raw label `MyMemory（机器翻译）` only when its translation actually fills the Chinese field; do not attribute a branch that contributed no content. If neither branch contributes usable content, use the existing raw source `手动填写`. Do not apply Wiktionary's license to MyMemory output. The draft's machine-translation notice follows the recorded source, not current preferences.
- Finalize attribution when lookup completes. Editing the word, switching dictionaries, or changing language must not rebuild it; saving and JSON backups preserve it verbatim. `Source` links only the two fixed dictionary sites and the existing Wiktionary/license allowlist. Unknown historical formats remain plain text, without new interpretation or special handling. Keep full attribution and modification notices available in entry details. See [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) for content licensing and MyMemory service references.
- Speech uses the Web Speech API, not dictionary audio. On each user click, read the latest `getVoices()`. Among voices whose language is `en-US` after case normalization and underscore handling, prefer the default voice, otherwise the first match. If there is no match or voices have not loaded, leave `voice` unspecified and retain `lang = 'en-US'`, rate `0.85`, and cancellation of previous speech. Start synchronously from the click; do not wait for `voiceschanged` or replay automatically. Re-select on later clicks. Interface language does not affect voice selection. A US preference is not a guarantee that the device has a US voice; some voices process text online, and availability or offline operation is not guaranteed.

## Validation checklist

These are reusable validation requirements, not a record of passed tests. Record the actual commands, environments, observations, and any untested boundaries rather than a fixed test count or a blanket completion claim.

1. **Automated contracts.** Cover persisted deletion and deletion of the last entry; invalid and nonexistent IDs; stale cross-connection IDs that must not remove a re-added word; transaction abort after a successful delete request and subsequent retry; export after deletion and restoration from an older backup. Cover field and timestamp validation, unique words, descending ID order, rollback, same-sense lookup pairing, Chinese completion, cancellation, timeouts, partial success, attribution, JSON round trips, duplicate skipping, and invalid or oversized backups. Include dual, single, and unlabeled accents, isolation between dictionary entries, and whole-segment phonetic length limits. Test each dictionary with fixed MyMemory and verify that the unselected dictionary is never requested. Cover preference defaults, storage exceptions, and deployment-directory isolation; dictionary-Chinese priority; exact MyMemory attribution; and no retries or alternate-service fallback. Use fixed synthetic dates in entry, storage, and backup tests, checking phonetics, raw source, v1 format, and absence of preference fields. Preserve complete locale-catalog checks and unchanged Unicode/source-data assertions; test both languages' dictionary hints and **Details & source** messages.
   - **Scoped legacy cleanup.** With synthetic valid and malformed legacy values, verify removal of exactly the two keys above, no legacy-value reads/logging, no enumeration or bulk clear, and preservation of all protected data. Cover missing keys, lazy storage-access exceptions, failure of either removal without suppressing the other attempt, repeated calls/mounts/reloads without markers, and store loading without a cleanup warning. Use isolated browser storage, not a user's profile.
2. **Bilingual viewport matrix.** Test both dictionaries at representative CSS widths of 375, 390, 393, 402, 414, 420, 428, 430, and 440px, plus 320px, a short 375×667 viewport, 844×390 landscape, and 768/1024/1440px tablet or desktop widths. Check both sides of 359/360, 639/640, and 1023/1024 breakpoints. This is not coverage of every physical device. Inspect actual workspace widths, desktop top alignment without stretching, and field columns; do not assume the old single-column 864px maximum. Include empty and populated notebooks, drafts, expanded details, long words, complete dual phonetics, realistic multiline translations and examples, and long sources. Inspect representative screenshots and same-content grayscale comparisons for missing-translation decoration, font fallback, visible keyboard focus, and horizontal overflow.
3. **Type size and targets.** Measure body text at 13px on phones and 14px on desktop with the default root, and 26/28px with a 200% root font. Inputs and text areas remain at least 16px; main controls, buttons, and `summary` elements remain at least 44px high; language, speech, close, and delete buttons remain at least 44×44px. The dictionary selector defaults to at least 44px/16px; only the specified ≥640px hover/fine-pointer environment with no coarse pointer uses a 32px minimum height and relative `var(--text-body)` text (`0.8125rem` at 640–1023px and `0.875rem` at ≥1024px, equivalent to 13px and 14px with the default 16px root font). Check the 639/640 boundary, touch and hybrid inputs, and natural selector growth at 200% text size. At 320px, enlarged text, and English “Looking up…”, allow header and lookup rows to grow. Confirm that the longest option and native arrow are not clipped and that labels and hint associations remain intact.
4. **Isolated-browser workflows.** Exercise delete confirmation and cancellation; first, middle, and last entry deletion; persistence after refresh; failure retaining the entry; neighboring details and drafts staying intact; keyboard focus after deletion; and language changes during operations. Exercise lookup, manual entry, all native disclosures, save and refresh, speech calls, file selection, and export followed by import at another origin. Select the same file twice and verify that a bad import leaves existing entries intact. Use mouse, touch emulation, and keyboard to open **Details & source** for every entry type, including manual and older entries with no definition or example. Show only populated optional fields while retaining dates and sources. Check complete licenses, modification notices, and safe links. Draft attribution, review guidance, and warnings, plus the word-list storage/sync/backup reminder, must remain visible. The sample action prepares only a draft without requests or writes, and loading or read failure must not masquerade as empty state. Compare all entry fields, phonetics, sources, licenses, and timestamps before and after collapsing and in exported JSON. Use synthetic data, mock APIs, and isolated browser profiles; do not operate on a user's notebook or send regression queries to external dictionaries or MyMemory.
5. **Language and orientation changes.** With drafts and disclosures open, switch languages and orientation, and test 1023→1024→1023 on the same mounted page. Preserve field nodes, values, selections, disclosure state, and saved data. Breakpoints must not reset focus. An actual language-button click may move focus to that button through native behavior; do not force it back. Rotation must not reset locale. Confirm deployment-scoped preference restoration and current-page switching when storage is unavailable. Check localized hints, source links, dates, and page metadata without changing entries or backup content. Avoid empty-state directions such as “above” that contradict the two-column desktop layout.
6. **Async behavior and failures.** During delayed or failed lookup and import, switch locale and viewport without interrupting the operation. Verify that the synchronous lock blocks conflicting actions, cancellation and generation guards prevent late results from overwriting newer drafts, duplicates do not overwrite entries, and failed saves preserve drafts. Switching dictionaries must cancel in-flight requests and suppress late results without re-querying or changing completed drafts or their attribution; switching is blocked during save, delete, import, and export. Verify the **FreeDict**/**EnglishDict** labels, complete service-name `title` attributes, full attribution, and naturally wrapping dual phonetics. `modelContext` drafts remain visible; registrations do not multiply when locale or dictionary changes. Later queries use the latest dictionary with fixed MyMemory. Static titles and descriptions remain English, runtime warnings use the latest locale, and unknown/cancellation errors keep their identity.

Manually verify Safari's software keyboard, focus zoom, expanding or collapsing browser chrome, landscape safe areas, VoiceOver, system file selection and downloads, and actual speech on a real device. Record emulated and real-device results separately. Live third-party availability and manual entry after service failure can be checked separately; mock responses are not evidence of live upstream availability. Do not report a service or device check as complete unless it was actually performed.
8. **Static deployment.** Check assets and home links at both root and repository subpaths. Development, preview, and production addresses have independent browser data. There is no PWA, and browser caching is not an offline guarantee. Actual publication also requires successful Actions execution and a visit to the deployed site.
9. **Artifacts and legal notices.** Verify that the emitted third-party notice matches the source file. Preserve React, ReactDOM, Lucide, and Feather copyright, permission, and disclaimer text verbatim. Do not include `.env`, SQLite databases, private backups, secrets, or the entire project directory in deployment artifacts. ### Reusable density comparisons

## Build and deployment boundaries

- Maintain source in `src/`; `dist/` is reproducible output and must not be edited directly or committed. Keep Vite's relative `base: './'`. Public frontend code and variables cannot keep secrets.
- Preserve Vite's `third-party-notices` plugin and its `generateBundle()` asset emission. It reads the root `THIRD-PARTY-NOTICES.md` and emits that same filename into `dist/`. Translating comments must not remove or change this behavior.
- CI installs from the frozen lockfile, then checks, tests, and builds. It uploads only `dist/`. Deployment depends on the build job. Default permissions are `contents: read`; only the deployment job adds `pages: write` and `id-token: write`. The `pages` concurrency group serializes deployments without cancelling an in-progress deployment.
- Keep `.gitignore` protections for historical `.env`, `data/`, SQLite files, build output, and default-named backups. These patterns do not protect manual web uploads or files already tracked by Git. Inspect files before sharing and preserve historical data.
