# Wordbook maintenance guide

Wordbook is a React, TypeScript, and Vite application with a small Postgres-backed API deployed as a Vercel Function. See [README-ZH.md](README-ZH.md) for setup, usage, backups, and deployment, and [THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) for third-party content and dependency licenses.

Data flows from the page through `api-store.ts` and `/api` (`server/app.ts`) to `server/store.ts` and Postgres, from lookup through `vocabulary.ts` to third-party APIs, and through `backup.ts` to JSON files or validated transactional imports. `categories.ts` centralizes name and relationship validation, `library.ts` derives category/search results, and `practice.ts` copies immutable entry snapshots, including relationship arrays, without storage writes. `entry-content.tsx` shares the existing phonetic and source presentation without changing source allowlists, opaque historical text, `formatDate()`, or missing-translation treatment; save and delete remain outside that component. The application-owned HTTP API serves only the notebook and the session; lookups still go directly from the browser to third-party services. Dictionary selection has exactly two options; MyMemory is the fixed Chinese-completion service, not a configurable translation-provider framework.

## Development and checks

After changes, run:

```sh
pnpm check
pnpm test
pnpm build
pnpm preview
```

- `check` runs TypeScript type checking.
- `test` runs `node:test` through `tsx`. Database tests use PGlite, a real Postgres engine compiled to WebAssembly and run in-process; they need no server or environment variables. Network behavior of the pg driver and the hosted database is not covered.
- `build` generates `dist/`, including static assets and `THIRD-PARTY-NOTICES.md`.
- `preview` serves an existing static build without `/api`. Use `pnpm dev` with `.env.local` for full local testing.

Use pnpm to update dependencies and keep `package.json` and `pnpm-lock.yaml` together. Do not generate additional lockfiles with another package manager. If CI's frozen install fails, reconcile the dependency manifest and lockfile rather than removing `--frozen-lockfile`. In `pnpm-workspace.yaml`, keep `esbuild: true` for its required postinstall and `fsevents: false` to explicitly deny build-script permission; the retained `fsevents` dependency ships its native binary, and the explicit decision avoids undecided build approval in existing installations.

## Data contracts

- Trim words, normalize them to lowercase, and enforce uniqueness. Store reads and the default **Recently added** display use descending database-ID order, not creation time, including imports. Local filtering, **A–Z** sorting, and pagination operate on copies for display only; they must not mutate the stored collection or narrow exports.
- Postgres stores `categories (id, name, normalized_name UNIQUE)`, `words (id, word UNIQUE, the six other lexical columns, created TEXT)` and `word_categories (word_id, category_id)` with `ON DELETE CASCADE` on both sides, plus `login_failures`. IDs are `INTEGER` identity columns so drivers return JavaScript numbers. `created` stays `TEXT` holding the exact validated UTC ISO string. `ensureSchema()` creates missing tables with `IF NOT EXISTS` under a transaction-scoped advisory lock; any future schema change must be additive and backward compatible with running instances. Identity values are not reused, but unlike IndexedDB key generators, a rolled-back insert can leave a gap; never rely on contiguous IDs.
- Every write runs in one transaction that first takes the shared `WRITE_LOCK` advisory lock, so writers are serialized like the former readwrite transactions across both stores. Snapshots use `REPEATABLE READ READ ONLY` so words and categories are read consistently. Duplicate checks happen after taking the lock rather than relying on conflicts, so duplicates do not consume identity values.
- Keep `Entry`'s seven strings (`word`, `phonetic`, `translation`, `pos`, `definition`, `example`, `source`) and `DatedEntry` unchanged. `StoredEntry` adds required `categoryIds: number[]`, aggregated from `word_categories` in ascending order. Stored rows that fail entry or category validation reject reads as `storageInvalidRecord` without being rewritten. `Category` exposes `{ id, name }`; `LibrarySnapshot` is `{ words: StoredEntry[], categories: Category[] }`. Read and validate both tables atomically in `snapshot()`; retain `list()` as its words-only wrapper. Page refreshes publish one snapshot and exports reread the whole snapshot.
- Category names are trimmed, NFC-normalized, 1–80 UTF-16 code units long, and free of control characters. Identity uses lowercase NFC names independently of UI locale; internal whitespace and accents remain significant. Enforce at most 1,000 categories per library/file and 1,000 references per association/selection array. Local IDs are positive safe integers; copy, deduplicate, and numerically sort relationships, rejecting sparse arrays, malformed values, and dangling references. Use `Map` for user-supplied name resolution, not ordinary object keys. Do not add a word-count limit to ordinary library or bulk operations.
- `parseBackup(text)` returns `ImportBatch`, with a readonly name directory and entries containing the seven content fields, `created`, and readonly category-name arrays. `serializeBackup(snapshot, exportedAt?)` exports **v2 only**, with exactly `{ format: 'wordbook', version: 2, exportedAt, categories, entries }`; include all categories, even empty ones, and a required `categories` array on every entry. Continue reading exact v1 `{ format: 'wordbook', version: 1, exportedAt, entries }` envelopes, ignoring category-looking extras inside legacy entries and producing empty associations. Keep all unrelated entry fields excluded by the existing whitelist. Older apps cannot read v2; do not offer lossy v1 export.
- Backup entries use ascending local-ID order; directories and per-entry references use deterministic normalized-name order. Export names, never either kind of local ID, internal unique keys, preferences, UI selections, or practice state. Reject normalized-name collisions in the directory and undeclared references; deduplicate repeated entry references. Preserve the single `phonetic` string, raw source semantics, and UTC ISO dates. Validate every file entry, including later duplicate words. Names match across devices despite different IDs, reusing local IDs and spelling. Restoration is name-based merging, not rename synchronization: old backups may recreate a renamed category's old name.
- `importEntries(batch, { overwriteExisting, selectedCategoryIds })` validates and copies the complete batch and options before its first await. Resolve the full category directory, including empty categories and names referenced only by later duplicate words. Check merged category capacity and selected category existence in the transaction. For each first trimmed/lowercased word, associations become **existing ∪ backup ∪ selected**; v1 never clears associations. Default mode preserves existing lexical fields and `created`; only `overwriteExisting === true` fully replaces those fields, including empty values and raw `source`. Keep the local word ID and its associations, unrelated words, and existing recency. Only additions receive new IDs. First occurrence wins for both content and references; later occurrences are validated but skipped.
- Both import and export enforce field validation, **10 MiB UTF-8** and **10,000 entries**, plus category/reference limits. All word/category imports use one write transaction and roll back together; the server rechecks the 10,000-entry limit and caps the decompressed request body. Never clear the database or commit partial data. Return `{ imported, updated, skipped, classified, categoriesCreated }` only after commit: additions, chosen existing overwrites (even identical), and skipped content sum to the file entry count. `classified` counts distinct words gaining one or more associations, including categorized additions, and overlaps those content counters. Repeated imports of unchanged relationships do not increment it. `categoriesCreated` includes empty categories. Maintain paired localized feedback for all five counts.
- Extend the current `run()` transaction helper and SQL helpers in `server/store.ts` rather than introducing an ORM or repository framework. Inside transactions, await only database queries, never files or other network calls; bulk writes use `unnest` or `jsonb_to_recordset` so large imports stay a handful of statements. `save(value, categoryIds = [])`, category create/rename/delete, and `updateWordCategories(wordIds, change)` validate current references. Category rename preserves IDs; duplicate normalized names fail, but changing one's own name case is allowed. Category deletion and removal of all its relationships commit atomically while preserving every word; deleting a missing category is idempotent, and deleting words retains empty categories. Bulk updates return `{ changed, unchanged, missing }`, operate on latest records by ID, and never revive deleted/re-added words. Relationship-only writes touch `word_categories` only and never rewrite lexical columns.
- Delete words with `remove(id)`, accepting only positive safe-integer IDs and reporting success only after commit. A nonexistent ID is an idempotent success. Do not delete by word, which could let a stale page remove a newly re-added entry with the same word. Subsequent exports exclude deleted entries but retain empty categories; importing an older backup can restore content and creation times with new IDs. Do not add tombstones or a recycle bin.
- Preserve raw `source` values through saving, display formatting, and backup round trips. Interface-language changes must not rewrite stored Chinese source literals. Do not add storage cleanup or migrations as part of language or presentation work.
- Do not promise multi-user accounts, offline use, PWA support, or automatic migration of historical SQLite or IndexedDB data; former Pages users move data by exporting and importing backups. Keep private backups, historical databases, `.env*` files, and secrets out of source, test fixtures, and deployment artifacts.

## Server, API, and authentication contracts

- Routes (all JSON; non-GET requests must send `X-Wordbook: 1`): `GET|POST|DELETE /api/session`, `GET /api/library`, `POST /api/words`, `DELETE /api/words/:id`, `POST /api/categories`, `PATCH|DELETE /api/categories/:id`, `POST /api/word-categories`, `POST /api/import`. Vercel rewrites `/api/*` to `/api?route=…`; `apiRoute()` accepts both forms. Path IDs must be canonical positive decimal integers.
- Errors are `{ error: Message }` with existing message codes and parameters; the client accepts only shapes `parseMessage()` recognizes and falls back to generic codes. Unknown failures are logged server-side and reported as `storageUnavailable`; never send raw database errors or stack traces to the client.
- The server is the only validator that matters: keep validating every request body with the shared `entry.ts`/`categories.ts`/`backup.ts` rules even though the client validates first. The browser still parses backups before upload for immediate feedback and sends imports gzip-compressed (`X-Wordbook-Encoding: gzip`) above 64 KiB, which keeps uploads below Vercel's request-size limit. Ordinary bodies are capped at 1 MiB and imports at 10 MiB plus a small envelope after decompression. Library responses above 32 KiB are gzip-compressed when the client accepts it.
- Authentication fails closed: without `WORDBOOK_PASSWORD` (8+ characters), `WORDBOOK_SESSION_SECRET` (32+ characters) and `DATABASE_URL`/`POSTGRES_URL`, every route returns `serverMisconfigured`. The session cookie value is `v1.<expiry>.<HMAC>`; the HMAC key derives from both secrets, so rotating either signs out every device. Cookies are `HttpOnly; SameSite=Strict; Path=/`, plus `Secure` and the `__Host-` prefix on HTTPS. Password checks use HMAC verification rather than string comparison. Ten failures within 15 minutes pause sign-in globally; failures are recorded in `login_failures` and cleared on success.
- The page treats any `401` as signed out: it hides the workspace (keeping it mounted, so drafts and navigation state survive) and shows the sign-in form; a successful sign-in refreshes the notebook. Sign-out calls `DELETE /api/session` and reloads to drop in-memory data. Do not cache notebook data in browser storage.

### Scoped legacy translation-preference cleanup

- This explicitly requested cleanup is separate from language conversion or presentation work; the prohibition above on incidental cleanup still applies. Do not restore the retired translation service or its settings UI.
- Call `removeLegacyTranslationPreferences` from `src/dictionary-providers.ts` in the existing `src/page.tsx` mount effect, before store loading. Use a lazy storage getter exposing only `removeItem`. Attempt removal of exactly `${databaseName(location.href)}:baiduCredentials` and `${databaseName(location.href)}:translationProvider` from the current origin/directory namespace in `localStorage`; never read or log old values. Return normally if storage access fails. Handle removal failures independently so one blocked key does not suppress the other attempt. Neither failure blocks store loading or produces a page warning. Retry on every mount/reload, with no completion marker. The updated app must be visited at each specific origin and deployment directory to attempt cleanup; publication alone proves no real-user cleanup.
- Never enumerate or bulk-clear storage. This cleanup must not alter words, categories, schemas, backups, locale/dictionary preferences, other namespaces, unnamespaced lookalike keys, or any `sessionStorage`. Server-side schema changes are not part of preference cleanup.

## Page routes and navigation

- Keep `src/hash-route.ts` limited to pure helpers: `PageRoute` is `words | add`; `readRoute` parses exact supported hashes; `routeHash` produces `#/words` or `#/add`; `routeUrl` changes only the fragment of the supplied URL; and `isPlainNavigation` identifies ordinary link activation without intercepting modified or middle clicks. Do not add routing dependencies, a general router framework, or page components with large prop bundles. `Home` in `src/page.tsx` owns all route orchestration.
- Initialize from the live hash so a direct `#/add` visit does not flash My words. The default is `#/words`. Normalize a missing or unknown hash with `history.replaceState`, changing only the fragment and retaining pathname, query, and existing history state; do not add a history entry. Preserve root/subpath and trailing-slash semantics rather than reconstructing a deployment path.
- Use native header links for **My words** and **Add word**, with `aria-current="page"` and a non-color-only current-page indicator, not ARIA tabs. The brand link returns to My words without reloading. Preserve keyboard activation, modified clicks, middle clicks, and new-tab behavior. For ordinary activation, call `pushState` only when the target differs from the live URL, then synchronize React immediately. Same-route activation adds no history. Store page addresses only, never library search/sort/page, draft content, or practice state in history.
- Listen to `hashchange` for manual fragment changes and Back/Forward between different hashes; do not also listen to `popstate` and coordinate the same traversal twice. Read the current URL instead of replaying an event's old URL, and ignore queued events superseded by newer navigation. Keep `src/main.tsx` StrictMode and symmetric listener and `history.scrollRestoration` setup/cleanup, including effect replay.
- Preserve the module-level `databaseName(window.location.href)` and singleton API store. `databaseName()` already ignores fragments: both routes share the same preference namespace. Do not change its deployment-directory or trailing-slash behavior, schema, source handling, or data contracts. Routes add no persistence; a browser reload resets temporary library, draft, and practice state, while ordinary store refreshes preserve it.

## Build and deployment boundaries

- Maintain source in `src/`; `dist/` is reproducible output and must not be edited directly or committed. Keep Vite's relative `base: './'`. Public frontend code and variables cannot keep secrets.
- Preserve Vite's `third-party-notices` plugin and its `generateBundle()` asset emission. It reads the root `THIRD-PARTY-NOTICES.md` and emits that same filename into `dist/`. Translating comments must not remove or change this behavior.
- Vercel builds and deploys from its Git integration: the production branch should be `main`, other branches get preview deployments. Preview deployments share the connected database unless configured otherwise. `vercel.json` pins the Vite framework, `pnpm build`, the `dist` output, the `/api/*` rewrite and basic security headers.
- `.github/workflows/ci.yml` validates PRs targeting `develop` or `main`, pushes to those branches, and manual runs. It installs from the frozen lockfile, then checks, tests, and builds; it deploys nothing. Keep default permissions at `contents: read`, nonpersistent checkout credentials, and `pull_request` rather than `pull_request_target`.
- Server code under `api/` and `server/`, and the shared modules it imports (`src/entry.ts`, `src/categories.ts`, `src/backup.ts`, `src/messages.ts`), use explicit `.js` extensions on relative imports. Vercel runs these as Node.js ES modules without bundling, where extensionless specifiers fail at runtime. Do not import browser-only modules (React, `window`) from server code.
- The former GitHub Pages site is no longer updated by CI. Leave it online until its users have exported their IndexedDB data, then disable Pages in the repository settings.
- Keep `.gitignore` protections for historical `.env`, `data/`, SQLite files, build output, and default-named backups. These patterns do not protect manual web uploads or files already tracked by Git. Inspect files before sharing and preserve historical data.
